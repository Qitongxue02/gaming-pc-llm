# 常见报错与处置

先按本表定位，不要反复重启同一个失败配置。每项含"症状 → 原因 → 处置"。

## 显存类

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| `cudaMalloc failed: out of memory` | 显存不足 | 降档位（如 Q4_K_M→UD-IQ3_XXS）；降 `-c`；开 `--cache-type-k/v q4_0`；`--no-mmproj-offload` |
| `GGML_ASSERT(buffer) failed` | 第二实例启动（显存被占用） | `taskkill /IM llama-server.exe /F` 后再启动；启动脚本应带防重复检测 |
| 启动成功但推理极慢（几 tok/s） | 权重或 KV 溢出到内存/系统 | 看 nvidia-smi 是否满载；降上下文、降档位 |
| 空闲时显存只占 3–4GB | llama.cpp 惰性提交，正常 | 请求时才满载；不是服务坏了 |

## 上下文类

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| `CONTEXT_WINDOW_EXCEEDED` / 回答截断 | `-c` 小于请求长度 | 提高 `-c`；Harness 端降低携带的上下文（如关思考） |
| 128K 以上速度骤降 | 上下文过大 + MTP 草稿反噬 | 128K 关 MTP；16GB 卡甜点是 100K |
| 200K 起得来但 22 tok/s | 超甜点硬上 | 放弃 200K，回到 100K |

## 启动/脚本类

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| bat 双击命令错乱（`'xxx' 不是内部或外部命令`、中文拆碎） | bat 不是 GBK/CRLF | 用 GBK + CRLF 重写（scripts/gen_start_bat.ps1 生成） |
| `'n3.8-27B' 不是内部或外部命令` | 路径含空格/中文被拆 | 参数行用 `^` 续行且引号配对；模型名建议纯 ASCII |
| `error: invalid argument: not` | 参数被换行拆断 | 检查续行符 `^` 与行尾 CRLF |
| 启动即退、无日志 | 模型路径不对/文件损坏 | 核对 `-m` 路径与文件存在性 |

## 接入类（Harness）

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| "当前模型不支持图片" | 手动模型未声明 `input: [text, image]` | 改 cordis.patch.yml，见 harness-integration.md |
| 图片到达后被拒（报错在请求阶段） | 声明与真实能力不符 | 移除 `image` 声明 |
| 模型不在选择器里 | Provider/模型未生效 | 重启 Harness；核对 Provider ID 与 baseURL |
| 获取可用模型 401 | 凭据问题或上游无 GET /models | 查密钥；手动填模型 ID |
| 旧会话仍报"不支持图片" | 会话缓存旧判断 | 新建会话 |

## 模型质量类

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| 输出乱码/答非所问 | 量化过低（IQ2/三值）或未 `--jinja` | 换高档位；确保 `--jinja` |
| 说话方式怪异 | 模板不匹配 | `--jinja` 开；确认模型是 chat 版 |
| 中文差 | 该档位中文退化 | 换更高精度档位或 UD-* 动态量化 |

## 通用处置顺序

1. 看启动日志最后几行（`I/E/W` 前缀），E 即错误。
2. `nvidia-smi` 确认显存状态。
3. 单变量排查：一次只改一个参数，实测对比。
4. 记录能跑的配置（参数 + 速度 + 上下文），作为该机器"已知良好配置"。
